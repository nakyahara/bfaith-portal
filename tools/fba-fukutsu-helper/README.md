# FBA納品 福通伝票CSV (Chrome拡張・社内用)

Amazon Seller Central の **「ステップ3 – 印刷された輸送箱ラベル」** の画面から、
福山通運 iS-2 に取り込む**送り状CSV (26列)** をその場で作る。

## これで何が変わるか

```
旧: Seller Centralを見ながらスプレッドシートに宛先コードと箱数を手入力 → GASでCSV生成
新: 輸送箱ラベルを印刷したあと「📦 福通伝票CSV」を押す → CSVが落ちる
```

⭐ CSVの **U列「お客様管理番号」に Amazonの納品番号** が入る。
これにより毎晩22時の追跡番号の自動投入が、FCコードや箱数からの推測なしに
一意で決まる (同じFC宛の納品が同時に複数あっても取り違えない)。

## ⭐ 通信しない

必要な情報は**すべて画面に出ている**ので、画面のテキストから読むだけで完結する。

```
納品番号：FBA15GGL5J2X            → お客様管理番号 (U列)
納品先：HND2 – 350-1301 Japan …   → 荷受人コード + 郵便番号 + 住所
出荷商品: 輸送箱：5               → 伝票5枚
出荷日：2026年8月7日金曜日         → 出荷日付
```

そのため:

| | |
|---|---|
| 権限 | **なし** (`permissions` も `host_permissions` も空) |
| 設定 | **なし** (APIトークン不要・オプション画面なし) |
| サーバ | **不要** |
| 使える場所 | **どこでも** (社内LANでも自宅でも) |

インストールしたらすぐ使える。

## 使い方

1. Seller Central で納品手続きを進め、**ステップ3で輸送箱ラベルを印刷**する
2. 右下の **📦 福通伝票CSV** を押す
3. 納品番号・宛先・箱数を確認して **[この内容でCSVを作る]**
4. 落ちてきたCSVを iS-2 の「CSVエントリー」から取り込む → 送り状を印刷

**押したときだけCSVを作る。** 伝票発行は運賃が発生する不可逆な操作なので、
自動生成にせず「どの納品をいま出すか」を人が決める形にしてある。

**読み取れなければCSVを作らずに理由を出す。** 欠けたCSVを黙って渡さない。

## インストール

**zipで配る (更新が楽)**

```
https://<ポータル>/apps/fba-replenishment/download/extension.zip
```

を落として解凍 → `chrome://extensions` → デベロッパーモード → 「パッケージ化されていない拡張機能を読み込む」。
`make-icons.mjs` と `STORE_LISTING.md` はzipに含まれない。

**リポジトリから直接**

`chrome://extensions` → デベロッパーモード → 「パッケージ化されていない拡張機能を読み込む」
→ このフォルダを選ぶ。

いずれも設定項目はない。

## Chromeウェブストアへの提出

`STORE_LISTING.md` に、掲載情報・プライバシー申告・手順の下書きがある (非公開・組織内のみ)。
アイコンを作り直すときは `node tools/fba-fukutsu-helper/make-icons.mjs`。

## 構成

| ファイル | 役割 |
|---|---|
| `page-parse.js` | 画面テキストから納品番号・FCコード・住所・箱数・出荷日を読む |
| `fukutsu-csv.js` | 26列CSVの組み立て (**サーバ側と同一実装**) |
| `content.js` | ボタン・確認パネル・ダウンロード |
| `icons/` | 拡張アイコン (`make-icons.mjs` で生成。図柄=輸送箱に送り状) |
| `STORE_LISTING.md` | ウェブストア提出の下書き (**配布zipには入れない**) |

### 🚨 fukutsu-csv.js はサーバ側と同期している

`apps/fba-replenishment/fukutsu-csv.js` と**同じ結果を出さなければならない**。
`apps/fba-replenishment/tests/test-fukutsu-csv-parity.mjs` が両者の一致 (ヘッダー・列位置・
FCコード一覧・生成CSV・エラー文言) を検証しているので、片方だけ直すとテストが落ちる。

画面パーサのテストは `apps/fba-replenishment/tests/test-page-parse.mjs`
(実画面の表示テキストを写したものを使用)。

### 🚨 正規表現はリテラルで書く

`new RegExp('…\\s…')` は生成・転記のたびにエスケープが1段落ちて静かに壊れる
(2026-08-08 に実際に踏んだ)。パターンは必ず `/…/` のリテラルで書くこと。

## 宛先の出し方

| | |
|---|---|
| iS-2 のマスタに登録済みのFC | 荷受人コードだけ書く (現行と同じ・実績のある形) |
| **マスタ未登録のFC** | **住所・郵便番号・名前・電話番号も書く** |

Amazonが新しいFCを開いてもマスタ登録を待たずに伝票が出せる。
電話番号は iS-2 マスタ74件中70件が使う `(06)6333-4858`。
🚨 `TPFB` はマスタ上の名前・住所が `XHD1` のものになっているため「無いもの」として扱う。

## サーバ側のAPIについて

`/apps/fba-replenishment/ext-api/plan-csv` に同じCSVを返すAPIがあるが、
**この拡張は使っていない** (SP-APIの資格情報を持つホストが必要で、社外から使えないため)。
画面から読めなくなった場合の保険として残してある。
