# 選べるセット展開 (Chrome拡張)

ネクストエンジンの受注伝票画面で「選べる〇種セット」を実SKUの明細行に展開する社内用拡張。

## 何を自動化するか

モールで売れた「選べる〇種セット」は、組み合わせが無限で商品マスタに登録できないため
**架空の商品コード** (`selectae10-5` 等) で受注が入り、NEでは引当待ちに落ちる。
お客さんが選んだ実SKUは受注明細の **商品op** に埋まっている。

従来はExcelに商品opを貼って数式でSKUを抜き出し、NEの伝票で「セル選択→Enter→商品コード入力」を
1行ずつ繰り返していた (10件/日、セール時40件/日)。この拡張はそれを次の4アクションに縮める。

1. 伝票を開く → パネルに「展開する」ボタンが出る
2. 押す → 追加される明細行がプレビューされる
3. 「この内容でNEに入れる」→ NEが「貼り付けを完了しました」と出すので **OK**
4. 内容を確認して **更新保存** → 「商品計が一致していません。再計算しますか?」は **必ずキャンセル**

## 🚨 保存時の注意

追加された行には商品マスタの**単品価格**が入るため、そのまま再計算するとセット価格が
単品合計に化けて請求額とズレる。**「再計算しますか?」は必ず【キャンセル】**を押すこと。
パネルの上部にも常時警告を出している。

## 導入

1. Chrome → `chrome://extensions/` → デベロッパーモードON → 「パッケージ化されていない拡張機能を読み込む」
   → このフォルダを選ぶ
2. 拡張の「オプション」を開き、接続先 (既定 `https://wh.bfaith-wh.uk`) と
   APIトークン (`SELECT_SET_EXT_TOKEN`) を入れて「接続テスト」
3. NEの受注伝票を開くと、対象の明細行があればパネルが出る

## 🚨 接続先は Cloudflare Access の後ろにある

`wh.bfaith-wh.uk` は Cloudflare Access で保護されており、素で叩くと
cloudflareaccess.com のログイン画面へ 302 される (2026-08-08 実測)。

この拡張は `credentials: 'include'` で叩くことで、**ブラウザが持っている
CF Access のログインクッキーを使う**。拡張自体に認証情報を持たせないための選択。

そのため **同じブラウザで一度 https://wh.bfaith-wh.uk を開いてログインしておく**必要がある。
セッションが切れると拡張が「ログインセッションが切れています」と出すので、
サイトを開き直せば復帰する。

## マスターの管理

選択肢の定義は **楽天RMS Item API 2.0 の customizationOptions から自動取得**するので、
香りが増えても基本は何もしなくてよい。

自動で取れない分 (ganesh のように選択肢に商品コードが入っていないセット、
楽天の文字数制限でコードが切れているもの、モール側の表示名が商品マスタと違うもの) と、
おまけの優先順位は、ポータルの **「🎁 選べるセットの明細展開」** で編集する。

## 仕組みのメモ

- 拡張 → Service Worker → ポータル `/apps/select-set/ext-api` (x-api-key 認証)。
  content script から直接叩かないのは、CORS を避けるためとトークンをページ側に置かないため
- NE標準の **「明細入出力補助」** (メニュー→明細入出力補助) に値を流し込んで貼付けている。
  ダイアログを開かなくても `visibility:hidden` のまま値を入れてボタンを押せる (実機で確認済み)
- 明細グリッドの列位置は決め打ちせず、ヘッダーの見出しから引いている
  (NEの「表示設定」で列を隠せるため)
- グリッドの行の中にボタンを差し込むとNE側の再描画で消えるので、パネルはグリッドの上に置いている
- 解決できない選択肢が1つでもあれば展開しない (fail-closed)。従来どおり手作業に倒す
