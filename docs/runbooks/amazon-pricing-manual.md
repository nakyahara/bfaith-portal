# Amazon 価格管理 (自社プライスター) 操作マニュアル

<https://bfaith-portal.onrender.com/apps/amazon-pricing/>

## ① これは何のための道具か

Amazon の出品は 2,800 件ほどあり、値段を「いくらにするか」を 1 件ずつ頭で考えるのは無理がある。
いまはプライスター (月額サービス) が「カートに合わせる」などのルールで自動で値段を動かしている。

この道具は、**その仕事を自社でやるための土台**。ただし今は **値段を動かさない**。

たとえるなら、店の値札を貼り替えるロボットを作る前に、
まず「どの棚の、どの商品を、どういうルールで、いくらにするつもりか」を **全部ノートに書いて、毎日そのノートを見返す** 段階。
ノート (データベース) に溜まった「人の決めたこと」「ルールの判断」「人の採点」を、あとで AI が読んで、
「こういう時はこうする」を学ぶ。ノートが薄いうちにロボットを動かすと、2026 年 3 月の事故 (間違った値段が自動で送られた) をまた起こす。

## ② 全体の流れ

```
毎日 (自動)   Amazon の価格・カート・手数料・販売  →  Render のデータベース (mirror)
              ↓
画面を開く    1 出品 1 行で「いまの価格 / カート / 原価 / 粗利 / 下限 / 方針 / 判定」が出る
              ↓
人がやる      ・方針を決める (追従モード・赤字ストッパー・高値ストッパー) → 理由つきで記録
              ・「今日の判定」を見て 👍 妥当 / 👎 違う を付ける
              ↓
記録される    方針の変更履歴・判定・採点 (全部、書き換えできない形で残る)
              ↓
(まだ無い)    実際に Amazon へ送る  ← 別の段階。関所を全部つけてから
```

## ③ 各画面の使い方

### 出品一覧

上のカードに「価格データの日付」「判定の内訳」「⚠️ 赤字の疑い」「原価不明」が出る。
**まず ⚠️ 赤字の疑い を押す** — 今の価格が、原価と手数料から計算した下限より低い商品。これが一番見る価値がある。

| 列 | 読み方 |
| --- | --- |
| いまの価格 | 前日時点の自分の出品価格 (日次スナップショット) |
| カート | カート価格と、自社 / 他社 のどちらが持っているか |
| 原価 (税込) | NE 商品マスタの原価 × (1+税率)。セットは構成品の合計。**構成品に原価の無いものがあれば「原価不明」** |
| 粗利 (いま) | いまの価格で売れたときの概算。赤字はマイナス、最低粗利率未満は黄色 |
| 30日 | 直近 30 日に売れた数 (確定分なので 1〜2 週間遅れる) |
| 下限 (計算) | (原価 + 手数料) ÷ (1 − 手数料率 − 最低粗利率)。**これより下の値下げは提案されない** |
| ストッパー | 人が入れた赤字ストッパー / 高値ストッパー |
| モード | 追従しない / カートに合わせる / FBA最安値 / 最安値 |
| いまの判定 | ルールが「もし動くならこうする」。値上げ / 値下げ / 維持 / 保留 と理由 |

「方針」ボタンで、その商品の方針を変える。

### 方針を変える (ダイアログ)

- **追従モード**: 最初は「追従しない」のまま、見るだけでよい。試したい商品だけ「カートに合わせる」にする
- **赤字ストッパー**: これより下げない値段。**空でもよい** (原価が登録されていれば計算した下限が効く)。0 は入れられない
- **高値ストッパー**: これより上げない値段
- **上乗せ**: カートより 10 円安くしたいなら −10
- **最低粗利率**: 空なら 10%
- **変更の理由**: 必ず選ぶ。「その他」は文章が必要

保存すると「記録しました。価格は変わっていません」と出る。変更は**変更履歴**に残り、消せない。

### 今日の判定

ルールがその日の価格データと方針で出した判定の一覧。**実際には何も送っていない**。

- 「値上げ・値下げ」タブに出るものを見て、👍 妥当 / 👎 違う / ❓ わからない を押す。ひとことも書ける
- 方針を変えたあとは「いま判定を作り直す」を押す (同じ日でも作り直せる)
- 採点は溜めるほど価値がある。「ルールの判定に人がどれだけ同意したか」が、次の段階 (実際に送る) に進む判断材料になる

### 出品 (1 件の画面)

商品名を押すと開く。いまの状態・方針・判定の記録・方針の変更履歴・価格の推移 (90 日) が 1 画面に出る。

### 変更履歴

方針を「誰が・いつ・何を・前は/後は・なぜ」変えたか。SKU で絞れる。

## ④ 守るべきルールと理由

| ルール | なぜ |
| --- | --- |
| この画面で価格は変わらない、と信じてよい | 送るコードそのものが無い。テストが毎回確かめている |
| 赤字ストッパーに 0 を入れない (入れられない) | 旧ツールは「0 = 下限なし」で、競合の最安値まで無条件に下げた |
| 原価が「原価不明」の商品は、先に NE の商品マスタで原価を登録する | 原価が分からない商品は値下げの判定が出ない (保留のまま) |
| 方針を変えたら理由を選ぶ | あとで AI と人が「なぜそうしたか」を振り返るため |
| 👎 を付けるときは、ひとこと書く | 「違う」だけでは、ルールのどこを直すか分からない |

## ⑤ 困ったとき

| 症状 | 見るところ |
| --- | --- |
| 一覧が「まだ表示できません」 | mirror 表が無い。miniPC の daily-sync が Render に届いていない (jobs-monitor で `warehouse-daily-sync` を確認) |
| 価格データの日付が古い | `fetch-amazon-prices.js` (miniPC) が止まっている。jobs-monitor を見る |
| 判定が「保留」ばかり | 理由の列を読む。「原価不明」「FBA 手数料が取れていない」「カート無し」など、データ側の穴を先に埋める |
| 「今日の判定を自動で作れませんでした」 | 画面の上に理由が出る。開発者向けの詳細 = [`apps/amazon-pricing/README.md`](../../apps/amazon-pricing/README.md) |
